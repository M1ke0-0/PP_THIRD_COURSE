# Архитектура проекта

## Общая схема

```text
Пользователь
    │
    ▼
React SPA (frontend)
    │ HTTP / REST / JSON
    ▼
FastAPI (backend)
    │ SQLAlchemy
    ▼
PostgreSQL
```

Приложение проектируется как модульный монолит. Это соответствует масштабу учебного проекта: frontend и backend разделены, но backend остается одним приложением без лишней микросервисной инфраструктуры.

## Backend

```text
backend/
├── app/
│   ├── api/
│   │   ├── routes/       # обработчики HTTP-запросов
│   │   └── router.py     # сборка маршрутов API
│   ├── core/             # конфигурация, позже — безопасность
│   ├── schemas/          # Pydantic-схемы запросов и ответов
│   └── main.py           # фабрика и точка входа FastAPI
└── tests/                # автоматические тесты
```

На следующих этапах рядом появятся `models`, `services` и `db`. HTTP-слой будет принимать и валидировать запрос, сервисный слой — выполнять бизнес-правила, слой данных — работать с PostgreSQL через SQLAlchemy.

Префикс `/api` отделяет программный интерфейс от служебных страниц FastAPI. Начальный endpoint `/api/health` позволяет проверять доступность сервиса и в дальнейшем использовать эту проверку в Docker Compose.

## Frontend

```text
frontend/src/
├── app/                  # запуск, провайдеры, тема, маршрутизатор
├── pages/                # страницы приложения
├── shared/
│   └── api/              # единый Axios-клиент
├── styles/               # глобальные стили
└── main.jsx              # точка входа React
```

`AppProviders` — единая точка подключения глобальных провайдеров. Сейчас здесь Material UI, позднее здесь будет подключен Auth Context. Маршруты вынесены отдельно, чтобы на следующем этапе добавить layout и защиту страниц по ролям.

Axios-клиент использует `VITE_API_URL`, поэтому адрес backend не зашит в компонентах и может отличаться при локальном и контейнерном запуске.

## Принятые ограничения

- роли и права проверяются backend, а не только интерфейсом;
- frontend не получает правильные ответы активной попытки;
- сервер хранит `deadline_at` и остается источником истины для таймера;
- вариант теста формируется один раз и сохраняется;
- ответы сохраняются на сервере до завершения попытки;
- Redux, Alembic, Redis и микросервисы не используются согласно ТЗ.
