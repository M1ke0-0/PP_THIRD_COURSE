## 1. Задача

Во время теста студент не должен иметь возможности:

- переключиться на другую вкладку или программу;
- открыть браузер и искать ответы;
- закрыть тест и вернуться к нему позже;
- открыть инструменты разработчика и подсмотреть ответы в коде страницы.

Для Windows и macOS эту задачу решает **Safe Exam Browser (SEB)**, но клиента для Linux у SEB нет.
Поэтому мы делаем свой клиент-киоск для Linux и учим сервер принимать как его, так и официальный SEB.

### Из чего состоит решение

1. **Сервер на Django.** Тесты, попытки, таймер, проверка ответов, статистика. Один на весь университет.
2. **Клиент-киоск (Electron).** Открывает только сайт тестирования, в полноэкранном режиме, без адресной строки, меню и вкладок.
3. **Киоск-сеанс Linux.** Отдельный пользователь `exam`, который при входе попадает прямо в клиент, а рабочего стола и других программ у него нет.
4. **Проверка на сервере.** Страницы теста открываются только из киоска или SEB, а все подозрительные события записываются в журнал.

## 2. Сравнение с Safe Exam Browser

| | Safe Exam Browser | Наше решение |
|---|---|---|
| **Платформы** | Windows, macOS, iOS | Linux (основная цель); клиент запускается и на Windows/macOS, но без системной блокировки |
| **Linux** | Клиента нет | Есть |
| **Стоимость** | Бесплатно, open-source (MPL-2.0) | Бесплатно, свой код |
| **Блокировка системы** | Глубокая: на Windows своя изолированная оболочка, на macOS — режим Assessment Mode | За счёт киоск-сеанса Linux (отдельный пользователь + Wayland-оболочка `cage`) |
| **Защита от виртуальных машин** | Есть обнаружение VM | Нет, только организационные меры |
| **Интеграция с LMS** | Moodle, Open edX и др. через SEB Server | Своя система, интеграция не нужна |
| **Проверка подлинности клиента** | Config Key и Browser Exam Key в заголовках запросов | Свой заголовок клиента; сервер может проверять и ключи SEB |
| **Настройка** | Файл конфигурации `.seb` через SEB Config Tool или SEB Server | `config.json` с адресом сервера |
| **Зрелость** | Много лет в университетах | Учебный проект |

### Вывод

- Если в аудитории Windows или macOS — лучше использовать официальный SEB, он надёжнее.
- Если компьютеры на Linux — используем наш клиент.
- Если есть и те, и другие — сервер принимает оба клиента (см. [раздел 7](#7-интеграция-с-seb)).

## 3. Архитектура

```
┌─────────────────────────────────────────┐
│  Компьютер в аудитории (Linux)          │
│                                         │
│  автовход пользователя exam             │
│        ↓                                │
│  cage (киоск-оболочка Wayland)          │
│        ↓                                │
│  Electron-клиент (kiosk mode)           │
│   • только адрес сервера тестирования   │
│   • нет новых окон, меню, DevTools      │
│   • сообщает серверу о потере фокуса    │
└──────────────────┬──────────────────────┘
                   │ HTTPS
┌──────────────────▼──────────────────────┐
│  Сервер университета (Linux)            │
│                                         │
│  Nginx → Gunicorn → Django              │
│   • тесты, вопросы, попытки             │
│   • серверный таймер                    │
│   • проверка: запрос пришёл из киоска?  │
│   • журнал нарушений                    │
│        ↓                                │
│  PostgreSQL                             │
└─────────────────────────────────────────┘
```

**Важно:** Django и база данных работают только на сервере. На компьютер студента сервер не ставится,
иначе база с правильными ответами окажется у студента.

### Как проходит тест

1. Компьютер включается и автоматически входит под пользователем `exam`.
2. `cage` запускает клиент на весь экран. Других окон и рабочего стола нет.
3. Студент входит под своей учётной записью и выбирает тест.
4. Сервер проверяет, что запрос пришёл из киоска, и создаёт попытку.
5. Ответы сохраняются на сервере после каждого вопроса.
6. Если страница теряет фокус, клиент отправляет событие на сервер, и оно попадает в журнал.
7. Когда время выходит, сервер сам завершает попытку со статусом EXPIRED, даже если клиент закрыт.
8. Преподаватель видит результат и журнал событий по каждой попытке.

## 6. Как это применять

### Разработка (macOS / Linux)

```bash
# сервер
source venv/bin/activate
cd backend
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver

# клиент (в другом терминале)
cd electron-app
npm install
npm run dev     # обычное окно с DevTools
npm start       # режим киоска
```

### Преподаватель

1. Создаёт тест, вопросы и варианты ответов.
2. Включает «Только из защищённого клиента».
3. Назначает тест группе и публикует его.
4. После экзамена смотрит результаты и журнал событий по каждой попытке.

### Экзамен в аудитории

1. Компьютеры включаются и сами открывают клиент (пользователь `exam`).
2. Студенты входят под своими учётными записями.
3. Преподаватель следит за аудиторией; нарушения видны в журнале.
4. После завершения теста клиент показывает результат и возвращается на страницу входа.

### Студенты на своих ноутбуках с Linux

Можно запустить клиент через `npm start` или AppImage, но тогда работает только защита внутри окна: системный Alt+Tab
не заблокирован. Сервер всё равно запишет каждую потерю фокуса в журнал. Для экзаменов с высокими ставками
нужны компьютеры аудитории с киоск-сеансом.

## 7. Интеграция с SEB

### Что такое SEB Server

SEB Server — это сервер ETH Zürich для массовой настройки клиентов SEB и наблюдения за ними во время экзамена.
Он подключается к LMS (Moodle, Open edX и др.) через их собственные API. Готового API, куда наша Django-система
могла бы «отправлять события», у него нет. Для нашей задачи SEB Server **не нужен**.

### Как принять официальный SEB (Windows/macOS) нашим сервером

1. В SEB Config Tool создаётся файл `.seb`, в котором стартовый адрес указывает на наш сервер.
2. SEB добавляет к каждому запросу заголовки:
   - `X-SafeExamBrowser-ConfigKeyHash` — SHA-256 от полного URL запроса + Config Key;
   - `X-SafeExamBrowser-RequestHash` — SHA-256 от полного URL запроса + Browser Exam Key.
3. Преподаватель сохраняет Config Key в настройках теста.
4. Django при каждом запросе к странице теста считает `sha256(url + config_key)` и сравнивает с заголовком.
   Совпало — запрос пришёл из SEB с правильной конфигурацией.

Так один сервер принимает и наш Linux-клиент, и официальный SEB. Это возможное расширение фазы 2 (+1–2 дня).

Перед реализацией нужно сверить формат ключей с актуальной документацией SEB
(раздел «Browser Exam Key / Config Key» на safeexambrowser.org).

## 8. Технические детали

### Журнал событий

```python
class ExamEvent(models.Model):
    class Type(models.TextChoices):
        FOCUS_LOST = 'FOCUS_LOST', 'Окно потеряло фокус'
        NAVIGATION_BLOCKED = 'NAVIGATION_BLOCKED', 'Попытка перейти на другой сайт'
        NOT_KIOSK = 'NOT_KIOSK', 'Запрос не из защищённого клиента'
        SECOND_SESSION = 'SECOND_SESSION', 'Повторный вход во время попытки'
        TIME_EXPIRED = 'TIME_EXPIRED', 'Время вышло'

    attempt = models.ForeignKey('attempts.Attempt', on_delete=models.CASCADE, related_name='events')
    event_type = models.CharField(max_length=32, choices=Type.choices)
    created_at = models.DateTimeField(auto_now_add=True)
    details = models.JSONField(default=dict, blank=True)
```

### Проверка клиента на сервере

```python
def is_kiosk_request(request):
    return request.headers.get('X-Exam-Client-Key') == settings.EXAM_CLIENT_KEY
```

Ключ задаётся при сборке клиента. Это не абсолютная защита (ключ можно извлечь из клиента),
но обычный браузер без него страницу теста не откроет.

### Потеря фокуса (в клиенте)

```javascript
window.addEventListener('blur', () => {
  fetch(`/api/attempts/${attemptId}/events/`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json', 'X-CSRFToken': csrfToken },
    body: JSON.stringify({ event_type: 'FOCUS_LOST' }),
  });
});
```

В киоск-сеансе фокус уходить некуда, поэтому такое событие означает попытку обойти защиту.

## 9. Тестирование

### Автотесты Django

- обычный браузер (без заголовка клиента) не может начать тест с `require_kiosk`;
- просроченная попытка не принимает ответы и получает статус EXPIRED;
- нельзя начать попытку сверх лимита;
- нельзя открыть вторую активную попытку;
- студент видит только свои попытки, преподаватель — только свои тесты;
- событие из клиента сохраняется в журнал.

### Ручной чек-лист (Ubuntu 24.04, киоск-сеанс)

- [ ] После входа сразу открыт клиент, рабочего стола нет
- [ ] Alt+Tab ничего не делает (других окон нет)
- [ ] Alt+F4 / закрытие окна не закрывают тест до его завершения
- [ ] F12, Ctrl+Shift+I не открывают DevTools
- [ ] Ctrl+R, F5 не сбрасывают попытку (ответы сохранены на сервере)
- [ ] Ссылка на внешний сайт не открывается
- [ ] Правый клик не работает
- [ ] Переключение на другую консоль (Ctrl+Alt+F3) не даёт войти в систему
- [ ] Выдёргивание сетевого кабеля не теряет уже сохранённые ответы
- [ ] Обычный браузер не может открыть страницу теста

## 10. Развёртывание

### Компьютер в аудитории (Ubuntu 24.04)

```bash
sudo apt install cage
sudo dpkg -i exam-kiosk_1.0.0_amd64.deb
sudo useradd -m -s /bin/bash exam
```

Дальше:

1. Включить автовход пользователя `exam` в дисплейном менеджере (GDM: `/etc/gdm3/custom.conf`).
2. Сделать сеанс пользователя `exam` единственным: `cage -- /opt/exam-kiosk/exam-kiosk`.
3. Убрать у пользователя `exam` права sudo и доступ к другим программам.
4. Отключить лишние текстовые консоли (`NAutoVTs=0` в `/etc/systemd/logind.conf`), чтобы через Ctrl+Alt+F3 нельзя было войти в систему.

Точные шаги будут в скрипте настройки (фаза 5) после проверки на виртуальной машине.

### Сервер университета

```bash
sudo apt install postgresql nginx python3.12-venv
# создать базу и пользователя PostgreSQL
# backend/.env: DJANGO_DEBUG=0, DJANGO_SECRET_KEY, DJANGO_ALLOWED_HOSTS, POSTGRES_*
pip install -r backend/requirements.txt gunicorn "psycopg[binary]"
python manage.py migrate
python manage.py collectstatic
gunicorn config.wsgi:application --bind 127.0.0.1:8000
```

Nginx проксирует запросы на Gunicorn и раздаёт статику; HTTPS через Let's Encrypt или сертификат университета.
Gunicorn запускается как systemd-сервис.

## 11. Ограничения и риски

| Риск | Что делаем |
|---|---|
| Телефон или шпаргалка рядом с компьютером | Только контроль в аудитории — программно не решается |
| Студент запускает клиент на своём ноутбуке и переключается в другие окна | Сервер записывает каждую потерю фокуса; важные экзамены — только в аудитории |
| Клиент запущен внутри виртуальной машины | Обнаружения VM нет; в аудитории это невозможно без прав администратора |
| Извлечение ключа клиента и подделка заголовка | Ключ меняется перед сессией; дополнительно — разрешённые IP-адреса аудитории |
| Падение сети во время теста | Ответы сохраняются после каждого вопроса; таймер идёт на сервере |
